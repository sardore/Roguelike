# 관전 (화면 이미지 방식)

2026-10-29: 상태를 보내 관전자 쪽에서 게임 렌더러를 다시 돌리던 방식(r1)을 버리고, **호스트의 화면 이미지**를 보내는 방식(r2)으로 바꿨다.
r1은 관전자 쪽에 가짜 게임 상태를 만들어 게임 코드(조사 창, 카메라, 시각 이동, 시야)를 그대로 돌려서, 렌더 루프의 "관전이면 건너뜀" 분기마다 빠진 기능이 생겼다(캐릭터 멈춤, 닫히지 않는 창, 있지도 않은 칸 설명).

## 동작

- 호스트: `Spectate.observe`가 게임 캔버스(`#game`)를 긴 변 960px 이하로 줄여 JPEG(품질 .62)로 만든 뒤 관전자마다 한 번씩 보낸다. 관전자가 있으면 0.5초, 없으면 1.5초마다(사망 재생용으로 계속 기록).
  전송 대기량이 300KB를 넘으면 그 프레임은 건너뛴다(밀리지 않음).
- 호스트 화면에 보이는 것만 나간다. 게임 상태(맵, 몬스터, 소지품)는 나가지 않는다. 시야 밖 정보가 새는 경로가 구조적으로 없다.
- 관전자: `#spectateView`(전체 화면)에 그림을 띄운다. 게임 상태·렌더러·입력 처리 없음(`state`는 null). 확대·이동은 그림에 대해서만:
  드래그 이동, 핀치/휠 확대(최대 6배), 더블 탭 또는 "맞춤" 버튼으로 전체 보기.
- 받는 쪽 검증: `data:image/jpeg;base64,…` 형식이고 70만 자 이하인 것만 화면에 올린다.
- 채팅, 방 목록, 서버 깨우기·재시도, 사망 재생(마지막 60장면)은 r1과 같은 서버 채널(`spectator.action`)과 방식을 쓴다. 프로토콜 태그만 `manru-spectate-r2`로 바뀌어 옛 버전과는 섞이지 않는다.
- 방송은 판을 하는 동안 항상 켜져 있다(끄는 기능 없음).

## 한계

- 관전자는 호스트의 화면 범위 밖을 볼 수 없다(호스트가 보는 화면 그대로). 확대는 그림을 키우는 것이라 선명도가 호스트 화면 해상도(최대 960px)로 제한된다.
- 호스트 폰에서 JPEG 인코딩 비용이 든다(프레임당 수 ms~수십 ms).
- 서버 쪽 변경 없음. 관전자 수 상한 5.
