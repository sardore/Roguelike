# 관전 기능 계획 (코드 변경 없음, 승인 대기)

작성 2026-10-28. 이 문서는 조사와 계획뿐이다. 아래 "결정할 것"에 답이 나오면 1단계부터 만든다.

## 0. 무엇을 만드는가 (확인 필요)

"관전"이 만루에서 뜻할 수 있는 것은 셋이다. 기본 가정은 **A**다.

| | 뜻 | 서버 | 비고 |
|---|---|---|---|
| A | 다른 사람이 하는 판을 실시간으로 본다 | 필요 | 메가리그의 관전과 같은 쓰임 |
| B | 끝난 판을 다시 본다(사망 재생) | 선택 | 기록 저장만 있으면 됨 |
| C | 지금 있는 디버그 전장 관전(`battleWatch57`)을 정식 기능으로 | 불필요 | 몬스터끼리 싸우는 모드 |

## 1. 이미 있는 것 (조사 결과)

- **같은 저자의 중계 서버**: `sardore/cp32-online-relay`(`server.js` 625줄, 의존성 없는 Node WebSocket, `/online`, 방 코드·큐·재접속 유예·목록 `browseClients`)와 `cp32-online-server`의 `render.yaml`(Render 무료 웹서비스, `/health`). 메가리그는 이걸로 방·관전자(`src/features/spectators.js`, 792줄: 관전 요청·이탈·채팅·관전자 수 알림)를 구현했다.
- **세이브 한 벌이 곧 화면 상태**: `SaveService.commit`이 행동마다 `GameState.project`로 상태를 직렬화한다. 1층 기준 72 KB, gzip 14.6 KB(층이 깊어지면 더 큼). `loadGameCore({state,settings})`는 저장소가 아니라 객체에서 불러오는 입구가 이미 있다.
- **저장을 건너뛰는 선례**: `state.debugBattle57`이면 `SaveService.request/flush`가 아무것도 쓰지 않고 돌아간다. 관전 상태도 같은 방식으로 막는다.
- **상태 없이 보이는 화면 선례**: 디버그 전장의 `battleWatch57`은 조작 없이 실제 렌더러로 전장을 그린다(`DEBUG_BATTLE57.watching`).
- **막힌 것**: 런타임 난수에 판마다 고정된 씨앗이 없다(`RngService.runtime()`). 그래서 "입력만 보내서 같은 판을 재현하는 방식"은 쓸 수 없다. 상태를 보내야 한다.
- Apps Script(통계 서버)는 요청에 응답만 하므로 실시간 전송에는 못 쓴다.

## 2. 확정된 결정 (2026-10-28 사용자 답)

- 뜻: **A 실시간 관전.** 사망 재생(B)도 같이 만든다(마지막 단계).
- 공개: **공개 목록**에 노출.
- 정보 범위: **호스트의 시야 범위만.** 관전자는 시점 스크롤과 확대·축소만 자유롭고, 그 외 입력은 엄격히 막는다.
- 채팅: 넣는다. **한 번 보낸다고 키보드가 내려가지 않게** 카카오톡처럼 만든다.
- 서버: **cp32 중계 서버(`wss://cp32-online-relay.onrender.com/online`)를 그대로 쓴다.** 아래 §3.

## 3. cp32 서버를 쓸 수 있는가: 된다. 서버 수정 없이.

`cp32-online-server`의 `server.js`에는 대전 규칙과 무관한 범용 관전 통로 `spectator.action`이 이미 있다.

| 동작 | 서버가 하는 일 |
|---|---|
| `announce` | 방송 등록(`liveMatches`). 8초 안에 다시 안 보내면 지운다 → 호스트가 1.5초마다 다시 보낸다 |
| `browse` | 지금 방송 목록을 받고 이후 갱신도 받는다 |
| `watch` / `leave` | 호스트에게 전달(누가 들어왔는지 알려 줌) |
| `snapshot` / `chat`(호스트→관전자) | 호스트가 `targetId`를 지정해 보낸다 |
| `chat`(관전자→) | 호스트에게만 전달 |

- 서버는 **관전자에게 퍼뜨려 주지 않는다.** 호스트가 관전자마다 따로 보낸다. 그래서 호스트 기기의 업로드가 관전자 수에 비례한다(상한을 둔다, 아래).
- 채팅은 호스트가 받아서 걸러 낸 뒤 모든 관전자에게 다시 보낸다(검열·속도 제한·길이 제한은 호스트 쪽).
- 메가리그 클라이언트는 `protocol === "mega-spectator-r20"`인 방송만 목록에 올린다. 만루는 다른 `protocol`(`manru-spectate-r1`)을 쓰므로 **서로 섞이지 않는다.**
- 위험: 같은 무료 인스턴스를 공유한다(접속 수·메모리), 15분 무트래픽이면 잠든다(첫 접속 30~60초). 관전 메뉴를 열 때 `GET /health`(CORS 허용)로 먼저 깨우고 "서버 깨우는 중" 표시를 둔다.
- 서버를 고치지 않으므로 `sardore/cp32-online-server`에 push할 필요도 없다. 나중에 한도나 규칙이 필요하면 그때 새 모드를 서버에 추가한다.

## 4. 시야 범위만 보내는 방법 (엄격)

조사 결과 `drawMap`은 `state`의 최상위 키 52개만 읽는다(`monsters player floor seen visible map branchTerrain105 decor items status …`). 읽는 키 대부분은 `"x,y"`를 키로 하는 칸별 지도(`archDecor1020`, `floorPattern1022`, `outerWall94`, `subthemeFloors972`, …)다.

- **허용 목록 방식**: 위 52개 키 외에는 아무것도 보내지 않는다(`keyPlan`, 숨은 벽, 특수 층 계획, 소지품 전체, 세이브 내부값 등은 구조적으로 나갈 수 없다).
- 칸별 지도는 `seen`에 있는 칸만 남긴다. `map`은 안 본 칸을 `VOID`로 바꾼다. 몬스터·아이템·장식·함정은 `visible`/`seen` 안의 것만. 안 본 방의 몬스터 위치는 나가지 않는다.
- 관전자는 `state`를 **복원 파이프라인(`restoreState`)에 넣지 않는다.** 생성·입구 보정 같은 부작용이 안 돌도록 위 키만 가진 읽기 전용 "보기 상태"를 만들어 그리기에 쓴다(저장 안 함, 입력 안 받음).
- 검증: ① 보낸 프레임에서 `seen` 밖 좌표가 하나도 없는지 검사하는 시험, ② 호스트 화면과 관전자 화면의 픽셀 비교(같은 시야로 일치).

## 5. 전송 규약 (`manru-spectate-r1`)

- 방송 `announce` 내용: `{protocol, matchId=판 id, cls, floor, turn, hp, spectators, startedAt, updatedAt, ended}`. 닉네임·기기 정보는 없다.
- 호스트 → 관전자: `snapshot`(`kind:"full"` 층 입장·`watch` 직후·재동기화, `kind:"delta"` 바뀐 키만). 키 단위 비교로 델타를 만든다. 큰 정적 키는 층마다 한 번.
- 용량 보호: 관전자 상한 8명(기본), 델타가 너무 크면 전체로 대체하고, 느린 소켓은 건너뛴다.
- 호스트가 받는 것: `watch`, `leave`, `chat`뿐. 그 밖의 메시지는 버린다.
- 호스트 쪽 켜고 끄기: 설정 패널 "관전 허용"(기본 **꺼짐**).

## 6. 채팅 (카카오톡식)

- 관전 화면 아래 입력줄 + 말풍선 목록(자기 글은 오른쪽). 호스트도 "관전 채팅"으로 같은 창을 연다.
- **키보드 유지**: 전송 버튼의 `pointerdown`/`touchstart`에서 `preventDefault()`로 입력칸의 포커스를 빼앗기지 않게 하고, 전송 후 입력칸을 비우되 다시 만들지 않으며 `focus()`를 유지한다. 엔터로도 전송(줄바꿈은 Shift+엔터).
- **키보드가 가리지 않게**: `visualViewport`의 크기 변화에 맞춰 입력줄을 키보드 위로 올리고, 말풍선 목록은 맨 아래로 스크롤한다.
- 글자수 120, 1초 1회, 제어문자 제거, `textContent`로만 그린다(HTML 해석 없음). 최근 200줄만 유지.
- 호스트 화면: 채팅은 메시지 로그 한 줄로 가볍게 알리고(입력창은 열 때만), 플레이를 가리지 않는다.

## 7. 단계

1. **전송 규약과 연결**: `src/game/spectate.js`(소유자 하나)를 `manifest`에 추가. 중계 연결, `/health` 깨우기, `announce`/`browse`/`watch`/`leave`. 시험은 로컬에서 `cp32-online-relay/server.js`(의존성 없음)를 띄워 한다(실서버에 시험 트래픽을 보내지 않는다).
2. **호스트**: 설정 "관전 허용", 허용 목록 프레임 생성(`seen` 필터), 델타, 관전자별 전송, 채팅 중계.
3. **관전자**: 타이틀 "관전" → 방송 목록 → 읽기 전용 화면(HUD: 직업·층·턴·체력·관전자 수), 시점 스크롤·확대, 입력 전부 차단, 채팅창.
4. **채팅 다듬기**: 키보드 유지, `visualViewport`, 속도 제한.
5. **사망 재생(B)**: 호스트가 보낸 프레임 열을 기기에 최근 N턴 보관, 사망 화면 "마지막 장면 보기"가 같은 관전 화면으로 재생.
6. 시험·기준선·문서, 실제 폰 두 대 확인.

## 8. AGENTS.md 규칙과의 관계
- 소유자는 `spectate.js` 하나. 같은 일을 하는 두 번째 함수·상태 필드는 만들지 않는다. 래핑·재대입·사후 보정 없음.
- 저장 형식과 localStorage 키는 바꾸지 않는다. 관전 상태는 저장하지 않는다(`state.debugBattle57`과 같은 자리에서 "저장 안 함" 조건을 하나로 합쳐 `state.spectator`도 포함).
- CSS는 `src/styles/`에만, 새 `!important` 없음. 설정 주소는 `<meta name="manru-relay">`(개발·QA 빌드는 비움, 통계와 같은 방식).
- 공용 그리기·입력 경로를 건드리므로 일반 플레이, 디버그 전장, 이어하기, 저장 복원, 벌집나무·벌떼·목매·비무장 종 원본 픽셀을 회귀 검사한다.
- 기준선(`screens`, `values`)은 의도한 변경만 갱신하고 커밋 메시지에 적는다.

## 9. 위험
- 보기 상태에 빠진 키가 있으면 그리다 예외가 난다 → 키 목록은 `drawMap` 읽기 기록으로 만들고, 시험에서 여러 층·분기·특수 층 화면을 그려 확인한다.
- 델타가 어긋나면 화면이 깨진다 → 20턴마다 전체로 재동기화.
- 호스트 폰의 배터리·데이터 → 관전 허용은 기본 꺼짐, 상한 8명.
- 호스트가 백그라운드로 가면 소켓이 끊긴다 → 방송이 사라지고 관전자에게 "방송 종료"를 보여 준다.
- 공개 채팅의 악용 → 호스트 측 차단(관전자 내보내기), 속도·길이 제한.
