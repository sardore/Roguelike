# 세이브 문자열 (설정 패널)

설정 패널의 "세이브 문자열" 구역에서 지금 진행과 계정 진행을 문자열 하나로 만들고, 다른 기기에서 그 문자열로 이어한다. 설정 패널은 탐사 중에만 열리므로 새 기기에서는 새 탐사를 시작한 뒤 패널을 열어 붙여 넣는다(지금 진행은 문자열의 진행으로 바뀐다).

## 형식
`MANRU1.<본문>.<검사값>`: 본문은 JSON을 deflate-raw로 압축해 base64url로 쓴 것, 검사값은 압축 전 JSON의 CRC32(16진 8자리). `CompressionStream`이 없는 브라우저는 압축 없이 `MANRU0`으로 만든다. 불러올 때는 줄바꿈·공백을 무시하고, `MANRU1`을 풀려면 `DecompressionStream`이 필요하다(풀린 크기 32MB 상한).

JSON: `{format:'MANRU_SAVE_STRING', version:1, build, at, run, account}`
- `run`: 방금 커밋한 활성 진행 세이브(`manru1004_active_run`에 저장된 그 문자열 그대로). 세이브 형식·`saveVersion1004`는 바꾸지 않았다.
- `account`: localStorage의 `manru…` 키 가운데 진행 세이브·트랜잭션 저널·옛 버전 키(`manru984_*`, `manruRC70_*`, `manruV<n>Save`)를 뺀 전부(튜토리얼 기록, 사망 기록, 볼륨·글씨 크기·카메라·패드 등 설정).

## 가져오기
1. 형식·검사값·크기·키 목록(허용된 계정 키만, 64개·1MB 이하)을 검사하고, `run`을 `parseEnvelope`로 검증하고 다른 빌드(`saveVersion1004`)는 거부한다. 여기서 하나라도 걸리면 아무것도 바꾸지 않는다.
2. 계정 키를 쓴다. 죽은 런 id(`manru1004_dead_runs`)는 두 기기의 것을 합치고, 마지막 사망 기록은 더 나중 것을 남긴다. 나머지는 문자열의 값으로 바꾼다. 쓰기는 읽어 확인하고, 실패하면 이전 값으로 되돌린다.
3. `loadGame({raw: run})`(이어하기와 같은 경로)로 진행을 적용하고 `commit`으로 활성 세이브에 쓴다.
4. 설정을 다시 읽도록 화면을 새로 고친다. 이어하기 버튼으로 이어간다.

## 시험
`savestring` 시나리오(`tests/scenarios.mjs`): 기기 A에서 만든 문자열을 기기 B(다른 진행, 자기 죽은 런 id가 있는 새 저장소)가 패널로 붙여 넣어 이어하고, 같은 세이브를 보통 방식으로 이어한 결과와 상태가 같은지(세이브 쓰기 번호·시각 제외), 계정 키가 따라왔는지(죽은 런 합침, 볼륨), 빈 문자열·엉뚱한 글·잘림·한 글자 변조·검사값 불일치가 거부되는지 본다.

## 알아 둘 점
- 같은 문자열을 여러 기기·여러 번 불러올 수 있다(퍼마데스의 되돌리기 제한은 두지 않았다).
- 설정 패널의 옛 "백업/이동"(파일 내보내기·가져오기·자동저장 불러오기) 버튼은 퍼마데스 정책으로 숨겨져 있던 것이라 지웠다. 3개 슬롯 구역은 이번에 건드리지 않았다.
