# 망령전 판돈: 설계 (아직 코드 없음)

사용자가 정한 규칙(`GHOST_BATTLE.md`): **전부 건다.** 지면 가진 것을 모두 잃고 그 망령은 사라진다. 이기면 상대의 것을 모두 가져간다. 한 판의 승패가 곧 정산이다. 이 문서는 그 규칙을 지금의 구조(통계 서버 시트 + 중계 서버 + 양쪽이 각자 실제 게임을 돌리는 대전)에서 어떻게 지킬지 정한다. **서버(Apps Script)를 바꾸므로 배포는 사용자가 해야 한다.** 그래서 코드를 짜기 전에 범위를 정해 둔다.

## 지금 구조에서 막아야 하는 것
1. **복제**: 같은 망령을 두 판에 동시에 걸어 둘 다 이기면 템이 두 벌이 된다.
2. **도망**: 지는 쪽이 접속을 끊거나 판을 닫아 잃지 않는다.
3. **위조**: 양쪽이 각자 계산하므로 한쪽이 "이겼다"고 거짓으로 알릴 수 있다.
4. **남의 망령 도용**: 플레이어 ID(4글자+2숫자)는 랭킹에 보이는 값이라 비밀이 아니다. 지금은 ID만 알면 남의 망령 목록과 본문을 받고 가짜 망령을 올릴 수 있다.

## 정한 것

### 1. 인증: 기기 비밀값
- 기기마다 **비밀값**(랜덤 32자)을 처음 한 번 만들어 이 기기에만 둔다. 서버에는 **해시**만 올린다(`ids` 시트: 플레이어 ID → 해시, 처음 올린 쪽이 임자).
- 망령 목록·본문 받기, 잠금, 정산, 전리품 받기는 모두 ID와 비밀값을 함께 보낸다. 비밀값이 틀리면 거절한다.
- 이미 쓰고 있는 기기는 처음 올릴 때 한 번 등록된다(먼저 오는 기기가 임자가 되는 닉네임 등록과 같은 방식). 비밀값을 잃으면(브라우저 데이터 삭제) 그 ID의 망령은 못 쓴다. 지금도 기기를 바꾸면 망령이 따로인 것과 같다.

### 2. 잠금: 대전에 걸린 망령은 한 곳에서만
- 대전을 찾기 시작할 때가 아니라 **짝이 맞은 뒤**(`session.commit`) 양쪽이 서버에 `lock(망령 id, 대전 id)`을 보낸다. 서버는 그 망령이 `alive`일 때만 `locked`(대전 id, 시각)로 바꾼다. 이미 `locked`이면 거절하고, 거절당한 쪽은 대전을 시작하지 않는다.
- 잠금은 **30분**이 지나면 저절로 풀린다(끊긴 판에서 망령이 영원히 묶이지 않도록). 단 정산이 들어와 있으면 풀리지 않고 정산이 우선한다.
- 선택 화면(`openPicker`)은 `alive`만 보여 준다(지금은 `taken`만 거른다).

### 3. 정산: 양쪽이 같은 말을 해야 한다
- 승패가 나면 **양쪽이 각자** `settle(대전 id, 내가 이겼다/졌다)`를 보낸다. 서버는 **서로 반대**로 들어올 때만 확정한다.
  - 확정: 진 쪽 망령 `taken`, 이긴 쪽 망령은 `alive`로 돌아감(이긴 쪽은 잃은 것이 없다), 진 망령의 **소지품과 장비 전부**가 이긴 쪽의 전리품 줄이 된다.
  - 둘 다 "내가 이겼다" 또는 둘 다 "졌다": 분쟁. 둘 다 `alive`로 되돌리고 잠금을 푼다(아무도 잃지 않는다). 분쟁 횟수는 시트에 남긴다.
  - 한쪽만 오고 다른 쪽이 **10분** 안에 안 옴: 안 온 쪽이 진 것으로 확정한다(도망은 패배: 문서 `GHOST_BATTLE.md`의 끊김 규칙과 같다).
- 정산은 한 번만 된다(대전 id당 한 줄). 같은 요청이 다시 오면 처음 결과를 돌려준다.

### 4. 전리품: 어디로 가나
- 서버 시트 `loot`에 줄로 쌓인다: `시각, 받는 사람 ID, 대전 id, 준 망령 id, 항목들(JSON), 상태`.
- 이긴 사람은 **다음 새 판을 시작할 때** 전리품이 시작 상자(첫 층 시작 구역의 일반 보급 상자)에 들어 있다. 받으면 상태가 `claimed`로 바뀐다(한 번만). 한 줄이 한 번의 승리다.
- 이유: 진행 중인 판에 갑자기 아이템을 넣으면 저장·세이브 검증과 부딪히고, 대전 중 판은 저장되지 않는다. 새 판의 시작 상자는 이미 있는 장치(`tutorialChest`)다.
- 항목이 너무 많으면 상자가 넘친다: 한 번에 최대 12개, 나머지는 다음 새 판에 이어서 준다.

### 5. 위조 방어: 서버가 계산하지 않는 한계 안에서
서버는 대전을 계산하지 않는다(중계는 메시지만 나른다). 그래서 **완전한 방어는 불가능**하고, 줄이는 쪽으로 간다.
- **받는 쪽 검증(이미 코드에 있음, 이 문서와 함께 넣음)**: 상대가 보낸 `hit`·`status`는 **상대의 차례일 때만** 받는다. 차례 밖에 쏟아 붓는 피해는 무시된다.
- **받는 쪽 검증(할 것)**: 한 번의 `hit`는 상대 망령의 공격 능력으로 낼 수 있는 값을 넘지 못한다(한 번에 받는 쪽 최대 체력의 일정 비율로 상한을 둔다). 상한은 실제 판을 돌려 보고 정한다. 지금 숫자를 정하면 정상 플레이를 끊을 수 있어 아직 넣지 않는다.
- **승패는 양쪽 일치(정산 3)**: 한쪽이 혼자 "이겼다"고 우겨도 정직한 쪽이 "졌다"고 하지 않으면 확정되지 않는다. 위조하려면 정직한 쪽의 플레이어가 실제로 죽어야 한다.
- **남는 구멍**: 정직한 쪽이 **연결을 끊게 만들면** 그 쪽이 진 것으로 확정된다(정산 3). 방해로 끊게 하는 공격을 막을 수 없다. 판돈에 쓰일 때의 알려진 한계로 둔다.
- 더 나아가려면 **판의 입력 기록을 서버가 다시 돌려 보는 검증**이 필요하다. 이 게임의 판은 난수와 상태가 크고 코드가 한 덩어리라 서버에서 재현하기 어렵다. 지금은 하지 않는다.

## 서버에서 바뀌는 것 (사용자가 배포)
`server/stats.gs`에 추가:
- 시트: `ids`(ID, 비밀값 해시, 시각), `loot`(위 4), 기존 `ghosts`의 `status`에 `locked`(+ 대전 id·시각 열 두 개 추가).
- 요청: `POST {ghostLock}`, `POST {ghostSettle}`, `GET ?view=loot`(받는 사람 본인), `POST {lootClaim}`. 모든 요청에 ID와 비밀값.
- 기존 `GET ?view=ghosts`/`ghost`에도 비밀값 확인을 붙인다.
- **새로 붙여넣고 "새 배포"(버전 올림)** 를 해야 반영된다. 안 하면 판돈이 없는 지금 동작 그대로다(클라이언트가 서버의 `ghostLock` 응답이 없으면 판돈 없는 연습전으로만 연다).

## 게임(클라이언트)에서 바뀌는 것
- `PlayStats`: 비밀값 만들기·보관, 요청에 붙이기.
- `Duel`: 짝이 맞은 뒤 `lock` 호출(거절되면 시작 안 함), 승패 뒤 `settle`, 새 판 시작 때 `loot` 받아 시작 상자에 넣기.
- 선택 화면에 **무엇을 걸게 되는지** 보여 준다: 이 망령의 소지품·장비 개수, "지면 이 망령과 소지품이 사라진다."를 확인 단계에 둔다(되돌릴 수 없는 일이므로 한 번 더 묻는다).
- 테스트: 서버를 흉내 내는 시트(이미 `stats-server.test.mjs`가 쓰는 방식)로 잠금 거절, 정산 일치/분쟁/시간 초과, 전리품 한 번만 받기를 확인한다.

## 사용자에게 받아야 하는 결정 (제 기본값을 적어 둔다)
| 결정 | 기본값 | 다르게 하고 싶으면 |
|---|---|---|
| 도망(끊김)은 패배 | 패배 | 무효로 하면 도망으로 판돈을 피할 수 있다 |
| 정산 시간 제한 | 10분 | |
| 잠금 만료 | 30분 | |
| 전리품 전달 | 다음 새 판의 시작 상자, 한 번에 12개 | 계정 창고를 따로 만들 수도 있으나 화면이 하나 더 는다 |
| 이긴 쪽의 망령 | 그대로 `alive` | 이겨도 일정 확률로 다치게 하는 규칙은 넣지 않는다 |
| 비밀값 | 기기 비밀값 + 서버 해시 | 계정 로그인은 이 게임에 없다 |

## 만드는 순서
1. 이 문서의 결정을 확정한다(기본값으로 가도 된다).
2. 서버 코드 + 서버 시험(시트 흉내). 사용자가 새 배포.
3. 클라이언트: 비밀값, 잠금, 정산, 전리품, 확인 화면.
4. 실제 서버에서 두 기기로 한 판(이 단계는 사람이 해야 한다. 제가 실제 서버에 접속해 볼 수 없다).
