# 망령 (죽은 계정): 1단계

죽은 계정 하나가 곧 **망령**이다. 죽는 순간의 캐릭터(직업·레벨·스탯·무술·장비·소지품 전부)를 서버에 남겨 두고, 뒤에 다른 사람과 실시간으로 맞붙게 한다(2·3단계). 이긴 쪽이 진 쪽의 템을 전부 가져가고 진 망령은 사라진다(전부 건다). **이 문서는 1단계(저장과 목록)만 다룬다.**

## 왜 시트인가
- 관전용 중계 서버(`cp32-online-relay`)는 메모리뿐이고 무료 서버라 15분 쉬면 잠든다. 거기 두면 망령이 사라진다.
- 통계 서버(Google Apps Script, `server/stats.gs`)는 시트에 쓰므로 남는다. 망령 저장은 이미 있는 죽음 기록과 같은 요청에 실린다.
- 실시간 대전(2단계)만 중계 서버를 쓴다.

## 게임 쪽 (`stats.js`, `PlayStats`)
- `ghostBody()`: `state.player`를 그대로 JSON으로 복사하고(위치·돌던 시간 같은 일시 값은 뺀다) 45000자를 넘으면 보내지 않는다.
- `recordDeath(cause)`가 죽음 기록(`record`)에 `ghost`(그 문자열)를 싣는다. 클리어(`End`)는 죽음이 아니므로 망령이 없다. 기존 큐와 같은 큐라 전송 실패 시 다시 보내고, 서버는 같은 id를 한 번만 받는다.
- 내 판 목록(`MINE`)에는 망령 본문을 넣지 않는다(크기).
- 숨은 통계 화면(타이틀 위쪽 글씨 7번)에 **망령 탭**: 이 기기(플레이어 ID)의 망령 목록(층·레벨·사인·남아 있는지).

## 서버 쪽 (`server/stats.gs`)
- 시트 `ghosts`: `time, id, owner, nick, cls, floor, level, cause, status, body`. 런 id마다 한 줄, 한 주인당 200개, 전체 2만 줄. `status`는 처음에 `alive`.
- **망령이 생길 조건: 깊이 순위권에 든 죽음만.** 서버가 죽음 기록을 쓴 뒤 그 판이 깊이 순위(게임이 보여 주는 판, 상위 `RANK_ROWS`=30칸)에 들었을 때만 망령을 남긴다(`depthRanked_`). 순위 밖이면 죽음 기록만 남고 망령은 없다. 순위는 끝난 판과 진행 중인 판을 판이 세는 대로 센다. `stats-server.test.mjs`가 확인한다. 순위는 나중에 밀려날 수 있지만, 한 번 남긴 망령은 지우지 않는다.
- 본문이 `=+-@`로 시작해 수식이 되지 않도록 앞에 `'`를 붙여 저장하고 읽을 때 뗀다. 본문은 JSON 객체여야 한다.
- `GET ?view=ghosts&owner=AAAA00`: 그 플레이어 ID의 망령 목록(본문 없음, 최신순 100개). `GET ?view=ghost&owner=…&id=…`: 주인에게만 본문.
- **코드를 바꿨으므로 Apps Script에 새로 붙여넣고 "새 배포"(버전 올림)를 해야 반영된다.** 안 하면 죽음 기록은 그대로 가고 망령만 저장되지 않는다.

## 알려진 한계
- 주소와 플레이어 ID를 아는 누구나 남의 망령 목록을 볼 수 있고 가짜 망령을 올릴 수 있다. 템이 오가는 3단계 전에 서명이나 서버 쪽 검증이 필요하다.
- 플레이어 ID는 브라우저마다 하나라서 기기를 바꾸면 망령도 따로다.
- 시트 한 칸 한도(5만자) 때문에 45000자를 넘는 캐릭터는 저장하지 않는다. 실제 판에서 얼마나 커지는지는 아직 재 보지 않았다.

## 다음 단계
2. 두 사람이 중계 서버에서 서로의 망령을 직접 조종해 아레나에서 싸운다(대전 씨앗을 서버가 정해 양쪽 난수에 넣고 입력만 주고받는다). 3. 대전 시작에 양쪽 판돈을 서버가 잠그고 결과가 일치할 때 승자에게 준다.
